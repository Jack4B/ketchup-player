# Skille w tym repozytorium

Wybór z zestawu `/workspace/skills-dev` (lista „Skille dla AI”). Kopiowane są tylko te, które pasują do Ketchup Player (Android TV + telefon, Kotlin/Compose, makiety, TDD i review). Pominięte celowo: `nextjs-app-router-patterns`, `nodejs-backend-patterns`, `php-modernization`, `php-security-audit` (inny stack), `ui-ux-pro-max` (baza webowych palet, nie 10-foot UI), `webapp-testing` i `e2e-testing-patterns` (Playwright/Cypress pod aplikacje webowe — produkt jest natywny; zrzuty makiet robi `docs/mockups/v4/screenshot.py`).

| Skill | Po co |
|---|---|
| `android-tv-ui` | Już był w repo: 10-foot UI, focus, overscan, D-pad. |
| `android-architecture` | Moduły, Hilt, warstwy — Faza 0 i dalej. |
| `mobile-android-design` | Material 3 i wzorce telefonu (ten sam APK). |
| `compose-adaptive` | Okna TV / telefon / tablet (`WindowSizeClass`). |
| `compose-component-design` | API komponentów `core:designsystem`. |
| `frontend-design` | Hierarchia i typografia makiet oraz UI (bez szablonowego wyglądu). |
| `test-driven-development` | Najpierw test, potem kod — szczególnie port `*Policy`. |
| `systematic-debugging` | Najpierw przyczyna, potem poprawka. |
| `requesting-code-review` | Review przed scaleniem PR. |
| `receiving-code-review` | Jak odpowiadać na uwagi (weryfikować, nie przytakiwać). |
| `code-review-excellence` | Jak samemu robić review. |

Skilli animacji (`emil-design-eng`, `improve-animations`, …) nie ruszano — zostały z wcześniejszego commita. `design-taste-frontend` też zostaje jako pomocniczy przy makietach.
